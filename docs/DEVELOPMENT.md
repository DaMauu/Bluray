# 开发指南

面向二次开发与维护：版本规则、提交前校验、发版流程。功能说明见 [使用手册](GUIDE.md)，实现细节见 [架构设计](ARCHITECTURE.md)。

---

## 一、版本号规则

- 四段式，从 `0.0.0.1` 起，每次更新 `+0.0.0.1`。
- 只增不减，作废的号不回收，避免版本歧义。
- **每次改动新建文件，旧版本永不覆盖**：`legacy/pt-bluray-assistant-vX.user.js`。
- 改版本必须同步三处，缺一不可：

```
// @version      0.0.0.N
原盘转载面板 (v0.0.0.N)
[PT助手] v0.0.0.N 已注入 @
```

## 二、提交前校验

```powershell
node --check legacy\pt-bluray-assistant-v0.0.0.31.user.js
```

语法通过不等于功能正确。涉及以下改动时，必须补对应回归：

| 改动范围 | 需覆盖的回归 |
|---|---|
| 标题 / 副标题排版 | 标题提取、字幕语言推断、主演截断 |
| 截图收集与图床 | 缩略图还原、同图去重、上传结果解析、尺寸复核 |
| 查重与词库 | 关键词回退、体积校验、词库命中与过期 |
| 断点与批处理 | 页号推进、已查集合、断点判活 |
| 站点适配 | 列表行识别、详情页解析、下载链接 |
| qB 推送 | 分类补设、文件名清洗 |

回归脚本为 Node 写的源码切片测试（放临时目录，不入库），全绿才允许交付。

## 三、发版流程

1. 从当前版本复制出下一个版本文件，改三处版本号。
2. 跑语法检查与全部回归。
3. 桌面只保留最新一版，旧版移入历史目录。
4. 更新 [使用手册](GUIDE.md) 与 [架构设计](ARCHITECTURE.md) 中受影响的部分。
5. 提交信息写清版本与改动点，推送分支。

## 四、编码约定

- 单文件内 `var` + `function` 声明，不用 `let/const`、不用箭头函数，与历史代码保持一致。
- 模块之间通过显式参数传值，不依赖隐式全局，避免“函数被插进别的函数体”这类结构性事故。
- 任何新增网络请求必须走统一的 `http()` 封装，便于限速与错误识别集中处理。
- 新增站点只改站点表与解析器，不动主流程。
- 日志要能自证：关键分支必须打印判定依据（命中关键词、体积差、图片宽度等）。

## 五、易错点

- 用 PowerShell 做整段字符串替换容易踩 CRLF 与中文块，改动大段代码时优先按行号拼接，事后必须 `node --check`。
- 拼接后要确认函数仍在顶层：曾被误插进别的函数体内，语法检查通过但运行时报未定义。
- 改面板布局时同时检查：列宽是否为 `minmax(0,1fr)`、容器是否溢出、方块是否等高。
- 内联样式与样式表冲突时内联优先；但优先修样式表，避免内联散落。
